# 中盘启发式搜索设计（v2）

> 修订说明：v2 修正 v1 中 AI 转写引入的错误——分配公式恢复为比值式 exp(−(d_i/d_best)·c)；删除"资源不足即淘汰"机制，改为保底送格；硬截断仅指 JS 候选筛选（0.9 窗口 + 死格排除）；死格不再声称"点开安全"；终止条件只保留预算耗尽；规模数字删除、以实测为准。

## 0. 目标与边界

本设计只解决一个问题：在无确定性落子的中盘局面（猜测局面），选择第一个点击的格子。

- 不使用蒙特卡洛树搜索（已投入一周验证，不可行）。
- 不给未展开的节点做任何数值预测：无乐观上界、无悲观下界、无估计公式。分配给节点的价值只有两种来源——实测（已展开）或结构性精确量（概率引擎的解计数）。
- 资源按规则流向证据最需要的地方；能从既有规则自然推导的行为，不单独设阈值或特判（无激活、无复活、无定案阈值 Δ）。
- 50/50 结构检测暂不纳入，待本搜索验证后再议。
- 确定性收尾（有安全格或可标注雷）由搜索以外的既有确定性逻辑处理。

## 1. 术语（全部完整定义）

- **招法节点**：棋盘局面 + "从中选择一个格子点击"的决策点。价值 = 所有已展开候选中点击价值最大者。
- **候选**：某招法节点候选池中的格子。候选池由 §3 的筛选方法决定，一经筛选即为定局（硬截断）。
- **运气节点**：一次点击后的自然随机展开，连接该点击与其全部结局分支。价值 = Σ 结局概率 × 结局子局面价值。运气节点永不截断：一旦创建，其全部数字结局必须立即全部展开为子招法节点（成本由 §8 保底保证）；爆炸结局不入树，价值显式 0。
- **结局**：点击格子后翻开数字 0~8，或爆炸。数字结局数量 ≤ 9；爆炸 = 1 − 生存概率，作为期望公式的闭合缺项。
- **死格**：可能值唯一的格子（点开无信息）。无需特殊处理（§3）。
- **安全格**：死亡概率为 0 的格子。与死亡概率 0.01%、0.02% 的格子完全连续，无任何结构性特殊地位。
- **死亡概率**：一个候选或局面的失败概率 = 1 − 其当前价值估计。
- **资源单位**：一次真实引擎调用的成本，记为 1。两类调用：局面分析（概率引擎）、结局观察（observe）。
- **c 表**：每层一个的指数衰减系数表。第 k 层使用 c[min(k, L−1)]，超出表长的层沿用最后一个值。
- **硬截断**：候选筛选（§3）。被截断的候选从未进入树，如同从未存在；永不回归。

## 2. 树的规范形式与硬规则

```
招法节点 s
 ├── 候选 T1 ──→ 运气节点(T1) ──→ 结局 v ──→ 招法节点 s_{T1,v}
 │                              └─ 结局 v' ─→ 招法节点 s_{T1,v'}
 ├── 候选 T2 ──→ …
 └── …（硬截断的候选不在树中，如同从未存在）
```

硬规则：

1. 两类节点严格交替：招法节点 → 候选 → 运气节点 → 结局 → 新的招法节点。
2. 树上不允许悬挂运气节点：运气节点一旦创建，其全部数字结局立即全部展开为子招法节点。因此加深之前树上的所有叶子必然是招法节点；此性质由构造保证，加深前以防御性断言检查。
3. 死格不进入候选池（§3 的筛选方法天然排除）。若某局面的候选池为空（只剩死格，几乎不可能发生），不特殊处理——任意指定一个死格作为最优解即可。（注释：可能值唯一推不出安全；若想严格，指定最小死亡概率者即可，一行成本，不作要求。）

## 3. 候选筛选（硬截断）

每个招法节点的候选池由一次局面分析（1 单位）产出的概率网格，按 JS Sweeper 的候选点方法筛选：

- **0.9 概率窗口**：候选 = 安全概率 ≥ 0.9 × 最优安全概率 的格（继承 JS 的 HARD_CUT_OFF 语义）。
- **死格排除**：可能值唯一（观测值唯一）的格不进入候选池（继承 JS 行为）。

这是**唯一的截断**：窗口之外的候选从未进入树。无任何其他移除路径——资源不足不淘汰（§8），搜索中途不裁枝。无激活、无复活：被截断的候选永不回归；若真正的优者在窗口之外，本搜索不会找到它——继承 JS 语义的固有代价，接受（§14）。

## 4. 价值递归（闭合）

```
叶子（深度 0 的招法节点）：   Ŵ₀(s) = H0(s)
深度 k 的招法节点：           Ŵ_k(s) = max over 已展开候选 of V̂_k(T)
                              若无任何已展开候选，Ŵ_k(s) = H0(s)
深度 k 的候选格子：           V̂_k(T) = Σ_v P(v|T)·Ŵ_{k−1}(s_{T,v}) + (1 − 生存概率(T))·0
```

- Σ_v P(v|T) = 生存概率(T)；缺失的 1 − 生存概率 即爆炸结局，价值显式 0。公式无缺项、无附加系数。
- 未展开的候选不参与 max——它的价值尚未被测量（§5"等待被搜索"语义）。每个招法节点的分析费已付，H0 恒存在，因此**递归处处有定义**。
- 爆炸结局不入树，其价值 0 是结构性精确量，不是估计。

## 5. 叶子启发式 H0 与深度语义

- **H0(s) = (4 × s_best + s_second) / 5**：s_best、s_second 为候选中最小、次小死亡概率对应的安全概率。若候选仅一个，次佳取 0（对应 JS 原语义：无第二存活格时 blendedSafety = 4/5·bestSafety1）。
- H0 不是免费的：它的输入来自对该局面的一次分析，取 H0 需先付 1 单位分析费。
- **"等待被搜索"语义**：树中每个招法节点的值恒有定义（最低为 H0）。H0 可以出现在期望公式的中间项，代表尚未展开到全局深度的分支——其结果暂时不可信。每轮加深后这些分支要么被展开（值更新为实测），要么继续以 H0 存在；搜索终止时按 §9 如实报告每个候选的深度与子树展开程度，绝不把待搜索部分冒充完整值。
- 运气节点永不截断（§1）：自然随机不可估计；每个结局子局面至少获得 1 单位分析（规则 B + §8 保底），期望公式不允许任何结局缺项——此项由构造保证。
- 深度定义：一个决策层 = 招法节点 → 候选 → 运气 → 新局面。加深 = 全局 d → d+1。只有同深度的值之间才做比较；不同深度之间的值不复用（节点骨架可复用）。

## 6. 资源分配

三个规则互不覆盖。每个分配动作必须标明它发生在哪一层、使用哪条规则。

### 6.1 规则 A —— 决策层（招法节点之下，候选之间）：按优秀程度指数分配

- d_i：候选格子的死亡概率输入（当前可得的最深实测估计）——未展开过的候选 = P(格子是雷)（概率引擎精确量）；已展开过的候选 = 1 − Ŵ(该候选)（当前深度下的估计，随加深更新）。
- d_best = 候选中最小的 d_i；c = c[min(当前层, L−1)]（初值全 2.0）。
- **w_i = exp(−(d_i / d_best) × c)**　　r_i = (本节点剩余资源) × w_i / Σ_j w_j
- 份额低于 1 的候选**不淘汰、不截断**——按 §8 保底处理。

端点行为（c = 2.0）：

- 死亡 1% 与 1.1%（比值 1.1）→ 份额约 **55/45**；
- 死亡 5% 与 40%（比值 8）→ 份额约 **100/0**（exp(−14) ≈ 1.1×10⁻⁷）；
- 中间强度参照：96/4 对应 c ≈ 0.45（该例子若要入文档，必须带自己的 c，不能挂在 c=2.0 名下）。
- 比值式对"相对差距"敏感：比值越接近 1，份额越接近均分（1% vs 1.01% → 约 50.5/49.5）。

**d_best = 0 的处理**（内层存在确定安全候选）：全部资源分配给安全格（多个安全格均分），其余候选得 0。安全格被充分展开；"先点安全格"由价值 max 链与免费信息事实导出（§4/§5），不是本公式的推导结果——公式只决定资源去向。

### 6.2 规则 B —— 运气层第一波：强制均匀探索

候选被展开（付 1 单位观察费）后，其全部结局子局面在全部被探索完毕之前，任何单个结局不得获得超过 1 单位的资源：每个结局子局面先各付 1 单位分析费，获取各自的 H0 或已有值。即使某结局概率为 99%，也必须等其余结局全部被探索过，剩余资源才进入规则 C。理由：运气层的每个结局局面除概率外地位完全相等——期望公式不允许任何结局缺项。

### 6.3 规则 C —— 运气层第二波：按死亡概率归一化

- D_v = 1 − Ŵ(结局子局面 s_v)；r(s_v) = (该候选的剩余资源) × D_v / Σ_v' D_v'。
- 死亡概率高的结局子局面获得更多资源：死亡意味着复杂度（只有被迫猜测才会带来死亡，猜测意味着该区域仍有未解析的决策结构）；"简单但高概率"的结局已在第一波看清（其 H0 误差预计较小，待测），不应继续占用资源。
- 每轮加深时，用最新深度下的死亡估计重新归一化、重新分配——规则 C 与加深轮动态耦合。
- 分母 ΣD_v' = 0（全部子局面确定安全）时死亡归一化无意义，回退为均匀分配——规则 C 唯一的安全回退点。

### 6.4 三规则的总体分工

规则 A 决定"选谁深挖"（择优，候选地位不对等——最终只会打出一个）；规则 B 决定"谁至少被看一眼"（期望完整性）；规则 C 决定"看清之后重点看谁"（复杂度导向）。决策层与运气层的不对称是设计意图：决策层按优秀程度倾斜，运气层第一波强制均匀。

## 7. 加深轮与叶子不变量

加深动作（全局 d → d+1）：

1. 全树资源分配重算：按最新深度下的死亡估计重新执行规则 A/C。单个节点重算成本 O(其候选数量)，全树合计 O(总展开节点数)，可忽略。
2. 每片叶子获得向上取整后的资源份额（至少 1 单位，§8）。
3. 每片叶子用其份额展开一层：分析自己（1 单位）→ 规则 A 分候选 → 达标候选（份额 ≥ 1 + 结局数）按规则 B 全探索结局 → 探索完毕按规则 C（本轮最新估计）分配剩余 → 其子招法节点作为下一轮叶子获得各自的规则 C 份额。
4. 加深完成后立即执行预算检查：预算耗尽 → 进入终止流程（§9）。

**叶子不变量（时刻成立，防御性断言）**：树的所有叶子要么处于当前全局深度（本轮已搜索，值可信），要么处于"等待被搜索"状态（份额已分配，结果暂时不可信）——不存在部分展开的中间状态参与价值比较。

值重算：加深后叶子值变化，祖先值自底向上重新聚合（纯算术：加权和与取最大，不调用引擎）；引擎调用只发生在叶子展开本身。

## 8. 资源保底、超支与内存

- **保底**：每片叶子每轮至少获得 1 单位（向上取整）。资源不足 1 单位不构成淘汰理由——直接送 1 单位进行观测，允许本轮实际消耗超出名义预算，由轮末预算检查兜底。
- **不淘汰**：树中不存在因资源不足而移除的节点；候选池一经 §3 筛选即定局。
- **内存**：树只增不减，内存上界与累计展开节点数线性相关；无中程释放。此前的"消除内存爆炸"承诺不再成立，长考内存表现以实测为准（§13 最坏情况项）。

## 9. 主流程与终止条件

0. 启动检查：若局面存在确定性落子（安全格或可标注雷），交既有确定性逻辑处理；搜索只在无确定性落子的局面启动。
1. 根招法节点支付 1 单位分析费 → 按 §3 生成候选池（硬截断在此发生）。若池中只剩一个候选，直接返回它（无其他选择，无需展开）——这是自然情形，不是终止机制。
2. 在当前全局深度 d 内展开：规则 A → 规则 B → 规则 C → 递归进入下一轮叶子。
3. 每轮结束检查预算：
   - 预算耗尽 → 返回根层当前价值最优者，并如实报告：评估深度 d、每个候选的子树展开程度。估值与真值的差额在无 UB/LB 约束下无界、无保证，其分布由语料测出并上报；绝不把部分展开的值冒充完整值。
   - 否则 → 加深一轮（§7），回到步骤 2。

**终止条件只有一条：预算耗尽。** 不设定案阈值 Δ。

## 10. 规模与复杂度

- 完全展开模式下，每加深一层节点数以 c̄×k̄ 增长（c̄ = 每局面平均候选数，k̄ = 每候选平均结局数；典型 expert 场面约 10×3）。具体数值以 anytime 实测为准，不预先给定。
- 预算集中于少数优秀候选的主链（规则 A）与高死亡分支（规则 C）；总引擎调用 ≤ 总预算 + 保底超支部分（超支量级 ≈ 末轮叶子数 × 平均展开成本；终止时如实上报实际消耗）。
- 全树资源重算成本 O(总展开节点数)，相对引擎调用可忽略。

## 12. 与 JS Sweeper 的关系（借鉴与差异）

**借鉴**：候选点方法（0.9 窗口 + 死格排除，即本设计的硬截断）；单层启发式 H0（blended safety 4:1，含无次佳时 4/5·best 的原语义）；"trivial 分析先行"的分层思想；其 1-ply 期望安全前瞻（secondarySafetyAnalysis）的概念内核——本设计的同深度展开是其多层推广。

**差异**：JS 的决策包含多个固定阈值与加权项（guessPruning、progress、fiftyFifty 影响、期望清除数等），本设计除继承的 0.9 窗口外无任何阈值，且无 UB/LB 估计；JS 受每节点毫秒级成本限制只能做 1-ply，本设计的资源单位为引擎调用，可做多层同深度展开；JS 的深度-1 与深度-5 数值不可比，本设计全程同深度比较。

**实证参考**：JS 在 5 盘实测中 1 胜 4 负、155 步（本仓库 ref/ 日志可复现）；其 0.9 窗口在解数 5.87×10⁶¹ 的局面筛出 5 个候选（实录日志可复现）。本设计正确性以语料实验判定，不凭推理断言。

## 13. 验证计划（防糊弄原则的落实）

- **前置设施**：建立整盘对弈 playout 基准（固定种子集，覆盖 expert 与大棋盘；目前代码库无此设施，是第一项必须完成的工作）。
- **等价性测试**：深度 1 搜索在相同盘面上与 JS Sweeper 对照推荐落子；分歧需分项归因（JS 另有 progress/fiftyFifty 等项，先修 H0 适配再谈其他）。
- **真值标签实验**（低成本先行）：cap 内盘面用 EndgameBruteforce 的逐候选精确胜数作为真值，直接测量深度 1/2 搜索估计的偏置与方差——不依赖 playout 设施。
- **逐项基准**：同一语料上分别测量"纯概率选点"（基线）、"深度 1"、"深度 2"、"c 表不同取值"、"窗口宽度 0.9/0.95/无窗口"的胜率、步数、被迫猜测次数、引擎调用数、最坏预算消耗——逐项前后对比，任何声称的改进必须在此数据上成立。
- **最坏情况**：大棋盘（100×100/2500 级）上的预算与内存表现（树只增不减，验证长考内存承诺）。
- **失败记录**：所有失败如实记录（包括本设计自己的缺陷），不以"调整参数后重测"掩盖。

## 14. 已知权衡与开放项（不掩盖）

- **0 结局无级联展开**：搜索模型对 0 结局的价值估计低于真实级联收益——"0 不特殊"裁决的固有代价，影响幅度需语料测量。
- **硬截断不可逆**：窗口外的候选从未存在；若领先者在深层暴露更大死亡而真正优者在窗口外，翻案不可能——继承 JS 语义的固有代价，接受。
- **H0 中间项**：期望公式中"等待被搜索"分支的值暂时不可信；搜索的上报包含深度与展开程度，但决策质量仍受其影响——语料测。
- **深度受预算限制**：完全展开必然撞墙，深度与宽度的权衡由 c 表控制——c 表行为需语料校准。
- **50/50 结构检测**：暂缓，搜索验证后再评估是否作为低成本结构剪枝纳入。
- **转置局面未去重**：当前模型按树展开，可能重复分析同一局面；是否需要转置表由实测成本数据决定。
- **内存单调增长**：无中程释放，长考内存表现待实测（§13 最坏情况项）。

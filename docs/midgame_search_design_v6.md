# 中盘启发式搜索设计（v6 基线版）

> 修订说明：v6 依据用户头脑风暴定稿的极简形态——迭代加深 + 完全展开 + 硬截断 + 兜底轮。规则 A/B/C、候选余额、c 表等聚焦机制全部搁置（不进基线；其是否复活由基线数据决定）。bruteforce 仍与搜索隔离（游戏层收尾通道，单游戏一次）。本版的全部机制只有：0.9 规则（窗口 + 斩杀）、H0 启发式、兜底轮、三个终止出口。
>
> v6.1 修订（用户裁决后）：
> 1. **删除深度配额**（原出口 4）：冗余保险丝（终止性论证后以 v6.2 的深度上界为准）。
> 2. **逐候选观察移到节点诞生时**：修正 v6 原稿 §4 与 §7 出口 3 的成本口径矛盾（"结局分布均已到手"要求观察先于检查）。生命周期总成本不变（观察只是提前支付），H0 因此与 JS blendedSafety（排除死格）对齐。
>
> v6.2 修订（用户第二轮裁决后）：
> 1. **撤回出口 4（本轮零展开）**：用户指出终盘规则——深度 = 未开格数 − 雷数 时必终盘（剩余未开格全部是雷）。轮次同步推进保证全树至迟第 U₀−M₀ 轮终盘（U₀ = 根未开格数）→ 出口 2 必然触发，无需"零展开"出口。
> 2. **修正 §2.3（重要）**：原稿把"候选列表空（全死格）"写成"定值停摆"（局面值 = 生存概率、不再展开）——起草错误，制造了零成本空转叶子。用户法则"全是死格，任意选择一个作为唯一找法"的正确实现：钦定生存概率最大的死格为**唯一候选**，照常展开（死格单结局）、深度照常推进；候选列表经此操作永不为空。
> 3. **终止性论证改为深度上界**（替代 v6.1 的叶子翻倍论证）：每片非终盘叶子每轮必推进、每种幸存路径深度 ≤ U−M，见 §7。

## 0. 目标与边界

本设计只解决一个问题：在无确定性落子的中盘局面（猜测局面），选择第一个点击的格子。

裁决（全部为不可谈判的设计约束）：

1. 不做蒙特卡洛树搜索（已投入一周验证，不可行）。
2. 不给未展开的节点做任何数值预测：无乐观上界、无悲观下界、无估计公式。节点价值只有两种来源——实测（已展开）或结构性精确量（概率引擎的解计数）；H0 是唯一被允许的启发式插值点（叶子值，见 §5）。
3. 不引入不必要的机制：本版聚焦机制（规则 A/B/C、候选余额、c 表、连开）全部搁置，所有叶子同等对待。
4. 铁律：轮内先完全展开、后斩杀；**节点内比较恒为同深度**（§6 论证）；任何比较不得跨越轮次混用新旧值。
5. EndgameBruteforce 是超重型调用：单游戏至多一次，仅游戏层收尾通道（§7）；中盘搜索全程不碰它，搜索树里遇到可暴力节点假装没看到。
6. 预算 = 时间盒（真实引擎调用上限），不是"谁深谁浅"的资源——本版预算只回答"还能跑几轮"，不回答"谁能深挖"。
7. 50/50 结构检测暂不纳入，待本搜索验证后再议。
8. 确定性收尾（有安全格或可标注雷）由搜索以外的既有确定性逻辑处理。

## 1. 术语（全部完整定义）

- **招法节点**：棋盘局面 + "从中选择一个格子点击"的决策点。价值 = 所有存活候选中点击价值最大者。
- **候选**：招法节点候选列表中的格子。候选列表 = 0.9 窗口 − 死格（创建时一次形成，§6）；一经硬淘汰即从树中删除，永不回归。
- **运气节点**：一次点击后的自然随机展开，连接该点击与其全部结局分支。价值 = Σ 结局概率 × 结局子局面价值。运气节点永不截断：创建后其全部正概率数字结局立即展开为子招法节点；爆炸结局不入树，价值显式 0。
- **结局**：点击格子后翻开数字 0~8，或爆炸。正概率数字结局数量 ≤ 9（零概率结局不建节点）；爆炸 = 1 − 生存概率，是期望公式的闭合缺项。
- **死格**：观测值唯一（正概率数字结局数 = 1）的格子，创建时由 observe 判定并排除。点开无信息；可能携带正死亡概率（观测唯一推不出安全）。
- **安全格**：死亡概率为 0 的格子；与死亡概率 0.01%、0.02% 的格子完全连续，无任何结构性特殊地位。
- **生存概率**：P(点击的格子不是雷) = 1 − P(格子是雷)。概率引擎的精确量。
- **安全率**：候选的存活前景。本版所有候选在斩杀时均已展开（形成即展开），故安全率 = 其价值估计 V̂（实测）——不存在未展开候选参与比较。
- **快照**：一轮的展开阶段完成后、全树自底向上统一重算得到的值集合。斩杀只用快照值。
- **H0**：叶子的启发式值，H0(s) = (4 × s_best + s_second) / 5；s_best、s_second 为候选列表（0.9 窗口 − 死格，诞生时形成）中最小、次小死亡概率对应的安全概率（次佳缺省 0，对应 JS 原语义 blendedSafety = 4/5·bestSafety1）。与 JS 的残余差异：JS 的混合取"全部活边 + off-edge 地板"，本版取 0.9 窗口——窗口内仅一候选时本版 H0 = 4/5·best 系统性低于 JS，由标签实验测偏置（§11）。H0 不是免费的：诞生成本 = 1 单位分析 + Σ窗口候选 observe（观察与候选列表形成共享，不重复付费），此后复用。
- **终盘节点**：叶子局面的所有隐藏格状态均已确定（判定：全部隐藏格 P(雷) ∈ {0,1}，即剩余局面只有一种摆法）。此类局面必胜（点开全部确定安全格），价值 = 1；到达终盘后不再展开。**终盘深度规则（用户裁决）**：未开格数 U、雷数 M 的局面，幸存路径沿程雷数不变、每次点击翻开一个非雷格，至多再点 U−M 次——届时剩余未开格全部是雷，局面必终盘。
- **硬截断**：0.9 规则的创建时执行（§6.1）。**硬淘汰**：同一 0.9 规则在每轮快照后的全域重筛（§6.2）。两者是树内容减少的全部途径。
- **资源单位**：一次真实引擎调用的成本，记为 1。两类常规调用：局面分析（概率引擎）、结局观察（observe）。
- **深度**：一个决策层 = 招法节点 → 候选 → 运气 → 新局面。全局深度 d 表示轮数。

## 2. 树：规范形式与硬规则

```
招法节点 s
 ├── 候选 T1 ──→ 运气节点(T1) ──→ 结局 v ──→ 招法节点 s_{T1,v}
 │                              └─ 结局 v' ─→ 招法节点 s_{T1,v'}
 ├── 候选 T2 ──→ …
 └── …（被硬淘汰的候选不在树中，如同从未存在）
```

1. 两类节点严格交替：招法节点 → 候选 → 运气节点 → 结局 → 新的招法节点。
2. 不允许悬挂运气节点：运气节点一旦创建，其全部正概率数字结局立即展开为子招法节点。加深之前树上的所有叶子必然是招法节点或终盘节点；此性质由构造保证，加深前以防御性断言检查。
3. 死格不进入候选列表（创建时判定）。若窗口内全部为死格（候选列表为空且非终盘），钦定生存概率最大（死亡概率最小）的死格作为**唯一候选（唯一招法，用户法则）**：死格只有一个正概率数字结局，该候选照常展开、深度照常推进。经此操作，**非终盘节点的候选列表永不为空**——不存在"定值停摆"状态（v6.2：原稿"局面值 = 其生存概率、不再展开"是错误写法，见修订说明）。

## 3. 轮、展开与快照（迭代加深骨架）

每轮 = 全局同步推进一层（d → d+1），四个阶段依次执行：

1. **展开阶段**：所有叶子（招法节点）完全展开一层（§4）。展开顺序不影响任何结果（所有叶子预算对等，无分配）。
2. **快照**：全树自底向上统一重算（纯算术：加权和与取最大；不调用引擎）。
3. **斩杀**：0.9 规则全域重筛（§6.2），删除被淘汰整枝并回收内存。
4. **终止检查**（§7）：根池 = 1 / 全终盘 / 预算不足（进入兜底轮）——任一触发则止；否则进入下一轮。

**完全展开的同步性（铁律字面成立的关键）**：每轮所有叶子同时展开一层，因此快照时所有叶子同深度；同一招法节点的全部候选在同一轮一起展开（不存在部分展开），故候选的值恰好来自同深度的孩子——**节点内的一切比较（max、斩杀）恒为同深度**。这使"不跨深度比较"成为构造性质，而非纪律约束。

**叶子状态**（每轮快照时）：新叶子（本轮诞生，值 = H0，下轮展开）、终盘叶子（值 = 1，永不展开）。非终盘叶子必在下轮展开（候选列表永不为空——§2.3 钦定兜底），无任何"停摆"状态。

## 4. 完全展开与成本构成

**诞生（付费节点）**：1 单位分析（概率网格）→ 0.9 窗口（用网格免费筛出）→ 窗口内**逐候选 observe**（每候选 1 单位：产出结局分布与爆炸概率，兼作死格判定；结果缓存）→ 死格排除 → 候选列表形成（此后只减不增）→ H0（在候选列表上计算）。

**首次展开轮**：存活候选全部展开——**第一波**：每个正概率结局子节点付 1 单位分析费；子节点诞生时立即支付其自身分析 + 窗口观察（同本流程）。

**一片叶子的生命周期成本 = Σ_窗口候选 1（observe）+ Σ_存活候选 结局数 × 1（第一波）。**

**展开原子性**：候选要么完整展开（全部正概率结局子节点同时建立），要么不展开——本版不存在部分展开状态；因此也不存在"运气节点悬挂"的中间态。

> 版本说明：v6 原稿写"候选列表在首次展开轮形成"——与 §7 出口 3 的"结局分布均已到手方可精确预估下一轮成本"矛盾（检查先于展开，观察却在展开时）。现值改为**诞生时形成**：总成本不变，观察提前支付；被斩杀枝上已付的观察成为可计量浪费（由斩杀统计记录，§12）。

引擎调用种类（全部）：根分析（1 单位）；节点诞生（1 分析 + 窗口观察）；第一波（每结局子节点 1 分析）；终止时兜底轮同此。值重算与斩杀判定是纯算术。

## 5. 价值递归（闭合）

```
叶子（尚未展开）：         Ŵ₀(s) = H0(s)
已展开的招法节点：         Ŵ_k(s) = max over 存活候选 of V̂_k(T)
候选：                    V̂_k(T) = Σ_v P(v|T)·Ŵ_{k−1}(s_{T,v}) + (1 − 生存概率(T))·0
终盘节点：                Ŵ(s) = 1
```

- Σ_v P(v|T) = 生存概率(T)；缺失的 1 − 生存概率 即爆炸结局，价值显式 0。公式无缺项、无附加系数。
- P(v|T) 来自创建时 observe 的缓存，无需重复调用。
- 本版不存在"未展开候选参与 max"的情形（形成即展开）；根层返回同样取实测 V̂ 最大者。
- 快照混合不同深度的子值（不同轮诞生的枝深浅不一）是合法语义：深浅只影响精度，不影响比较时代——节点内比较的同深度性由 §3 的同步性保证。

## 6. 硬截断与斩杀：0.9 规则的两次执行

同一判定逻辑（安全率 ≥ 0.9 × 本节点最优安全率才存活），两个执行时机：

**6.1 创建时筛选（硬截断）**：候选列表 = 安全概率 ≥ 0.9 × 最优安全概率 的格（0.9 窗口，继承 JS 的 HARD_CUT_OFF 语义），再排除死格（§4）。窗口之外的候选从未进入树。

**6.2 每轮快照后全域重筛（硬淘汰）**：每轮快照完成后，全树每个招法节点执行同一判定：安全率 < 0.9 × 本节点最优安全率 → 整枝删除（候选 + 运气节点 + 全部后代），整枝释放回收（freeSubtree DFS）。最优候选自身永不淘汰（0.9 × 最优 < 最优 恒成立）→ 候选列表不可能被清空。

- 本版所有候选在斩杀时均已展开，安全率 = V̂（实测）——不存在"未展开候选用 1−P 参与比较"的面板问题。
- 无激活、无复活：被淘汰的候选永不回归；若真正优者在窗口之外或在中途被淘汰，本搜索不会找到它——固有代价，接受（§12）。

## 7. 终止与兜底轮

每轮斩杀后依次检查三个出口：

1. **根层候选列表存活数 = 1** → 返回该候选（自然情形，无需继续展开）。
2. **全终盘**：所有叶子均为终盘节点（判定：全部隐藏格 P(雷) ∈ {0,1}）→ 全树结算，返回。
3. **预算不足展开下一轮** → 进入兜底轮。下一轮成本 = Σ 叶子成本，**可精确预估**：所有叶子在诞生时已完成窗口观察，存活候选与结局数均已到手，无任何上界猜测。

**终止必然性（为什么不需要深度配额、也不需要"零展开"出口）**：

- **深度有界（终盘深度规则，用户裁决）**：沿任何幸存路径，雷数不变、每次点击翻开一个非雷格。未开格数 U、雷数 M 的局面至多再点 U−M 次，届时剩余未开格全部是雷 → 局面完全确定 → 终盘。
- **轮次同步推进**：非终盘叶子每轮必产生子节点（真候选 ≥ 2 个结局，或钦定死格 1 个结局），要么终盘停住、要么本轮新生——因此**至迟第 U₀−M₀ 轮（U₀ = 根未开格数）全体叶子终盘** → 出口 2 必然触发。
- **预算后备**：每片非终盘叶子每轮展开成本 ≥ 1 单位，若名义预算先耗尽 → 兜底轮 → 出口 3。

两条路径必居其一：**终止必然发生**。原"深度配额"与"本轮零展开"两个出口都是冗余设计，已删除。

**兜底轮**（最后一轮，触发后不再有下一轮）：

1. 按死亡概率升序排列叶子（最优者在前；死亡概率 = 叶子候选列表内最小 P(雷)，即 1 − H0 的 s_best）。
2. 逐叶展开：每片叶子展开前检查其**精确成本**（= Σ 存活候选 × 结局数；诞生观察已付，数字全部在手）≤ 剩余预算 → 展开并扣费；不足 → 停止。无需保守上界。
3. 停止点之后的叶子 = **被抛弃**：不展开、不删除、保持旧快照值（或 H0），参与最终报告。
4. 兜底轮完成后：快照重算 → 终止报告（本轮不做斩杀——没有下一轮，斩杀失去意义）。

**报告（终止时如实上报）**：返回根层 max V̂ 的候选（并列时：死亡概率低者优先，再按坐标序——保证确定性可复现）；报告内容：评估深度、每个候选的子树展开程度与展开史、被抛弃叶子名单、每轮斩杀统计（淘汰候选数与删除节点数）、实际消耗 vs 名义预算。估值与真值的差额在无 UB/LB 约束下无界、无保证，其分布由语料测出。绝不把部分展开的值冒充完整值——兜底轮中新旧值的混合是终止时的报告行为，不是比较行为。

## 8. 规模与成本

- 完全展开模式下，每加深一层节点数以 c̄×k̄ 增长（c̄ = 每局面平均候选数，k̄ = 每候选平均结局数；典型 expert 场面约 10×3，即每层约 ×30）。实用深度以 anytime 实测为准（具体数字不预先给定）。
- 终止必然性见 §7：深度上界 = 未开格数 − 雷数（用户终盘规则）→ 至迟第 U₀−M₀ 轮全终盘；预算耗尽为并行后备，不依赖任何保险丝。
- 全树快照重算成本 O(总展开节点数)，相对引擎调用可忽略。
- 内存：树只增不减，硬淘汰是唯一的中程释放源；上限受预算约束（展开总量 ≤ 预算单位数）。

## 10. 与 JS Sweeper 的关系

**继承清单**（原样继承，来源可查）：候选点方法（0.9 窗口 + 死格排除）；H0 混合 4:1（含无次佳时 4/5·best 原语义）；"trivial 分析先行"的分层思想；1-ply 期望安全前瞻（secondarySafetyAnalysis）的概念内核。

**差异清单**（本版自有的）：多层同深度（JS 受毫秒级成本限制只能 1-ply）；每轮快照后全域斩杀（JS 仅在创建时筛一次）；完全展开的同步性（JS 一次性算完）；无 progress / fiftyFifty / expectedClears 等加权项；除继承窗口外无任何阈值、无 UB/LB 估计。

**实证参考**：JS 在 5 盘实测中 1 胜 4 负、155 步（ref/ 日志可复现）；其 0.9 窗口在解数 5.87×10⁶¹ 的局面筛出 5 个候选（实录可复现）。本版正确性以语料实验判定，不凭推理断言。

## 11. 验证计划（防糊弄原则的落实）

- **前置设施**：整盘对弈 playout 基准（固定种子集，覆盖 expert 与大棋盘；代码库目前无此设施，第一项必做工作）。
- **等价性测试**：深度 1 与 JS Sweeper 对照推荐落子。预期：候选集一致（同窗口同死格判定），分歧集中于 JS 的额外加权项（progress / fiftyFifty / expectedClears）——分项归因，不笼统"修 H0"。
- **基线表**：同一语料上分别测量"纯概率选点"（基线）、"深度 1"、"深度 2"、"深度 3"（预算分档）的胜率、步数、被迫猜测次数、引擎调用数、实际消耗率 vs 名义预算。
- **斩杀与兜底统计**：每盘记录每轮斩杀候选数、删除节点数、兜底轮抛弃叶子的数量与真实表现（用真值标签回查被抛弃/被斩杀者是否被误杀）。
- **真值标签实验**（低成本先行）：cap 内盘面用 EndgameBruteforce 逐候选精确胜数作真值，测深度 1/2 估计的偏置与方差；顺带统计死格携带正死亡概率的出现率。
- **最坏情况**：大棋盘（100×100/2500 级）预算与内存表现。
- **失败记录**：所有失败如实记录（含本版自己的缺陷），不以"调整参数后重测"掩盖。

## 12. 已知权衡与开放项（不掩盖）

- **深度浅**：完全展开必然撞墙（预估 2–4 层）——这不是缺陷而是基线事实，是后续任何聚焦机制的第一手数据来源。
- **预算不聚焦**："暴富花不完"问题的本版回答 = 不分配、人人平等；聚焦能力完全交由 0.9 线（存活池收缩）。
- **0.9 狠斩锁宽度**：只影响每叶的候选数（钦定死格叶为 1 子、真候选 ≥ 2 子）；终止性不依赖叶子增长——由深度上界保证（§7）。无需保险丝。
- **诞生即观察的浪费**：被斩杀枝的窗口观察已在诞生时支付（观察比 v6 原稿提前一轮）——总成本不变，但"已付观察的死枝"成为显式浪费，由斩杀统计（removedNodes）逐盘计量。
- **H0 的窗口 vs JS 的 off-edge 地板**：窗口内仅一候选时本版 H0 = 4/5·best，系统性低于 JS（JS 混入次佳 / off-edge 兜底）；窗口切 vs JS 全活边——由标签实验测偏置与方差。
- **死格边缘情形**：窗口全死格时钦定生存概率最大的死格为唯一招法（用户法则），照常展开推进——非近似、非停摆；实测统计出现率。
- **兜底轮混合新旧值**：报告行为而非比较行为，如实标注。
- **搁置机制清单**：规则 A/B/C、候选余额、c 表、连开（钱买深度）——全部列为二期候选，由基线数据裁决复活与否。
- **50/50 结构检测、转置表**：暂缓，实测成本数据后再议。

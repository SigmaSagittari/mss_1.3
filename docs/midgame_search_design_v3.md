# 中盘启发式搜索设计（v3 重构版）

> 修订说明：v3 重构文档架构（裁决 → 模型 → 机制 → 工程与验证，全景图前置），并新增更深的硬截断（冻结与可证截断，§10）与截断节点的删除机制（§10.3）。v2 的所有设计裁决保持不变。

## 第一部分 裁决与全景

### 1. 目标与边界

本设计只解决一个问题：在无确定性落子的中盘局面（猜测局面），选择第一个点击的格子。

裁决（全部为不可谈判的设计约束）：

1. 不做蒙特卡洛树搜索（已投入一周验证，不可行）。
2. 不给未展开的节点做任何数值预测：无乐观上界、无悲观下界、无估计公式。节点价值只有两种来源——实测（已展开）或结构性精确量（概率引擎的解计数、冻结后的精确值）。
3. 算力不浪费：资源按规则流向证据最需要的地方。
4. 不引入不必要的机制：能从既有规则自然推导的行为不单独设阈值或特判（无激活、无复活、无定案阈值 Δ）。
5. 截断判定只允许使用精确量（§10.5）——任何基于测量值比较的"软淘汰"不属本设计。
6. 50/50 结构检测暂不纳入，待本搜索验证后再议。
7. 确定性收尾（有安全格或可标注雷）由搜索以外的既有确定性逻辑处理。

### 2. 术语（全部完整定义）

- **招法节点**：棋盘局面 + "从中选择一个格子点击"的决策点。价值 = 所有已展开候选中点击价值最大者。
- **候选**：招法节点候选池中的格子。候选池由 §7 的筛选决定，一经筛选即为定局（硬截断①）。
- **运气节点**：一次点击后的自然随机展开，连接该点击与其全部结局分支。价值 = Σ 结局概率 × 结局子局面价值。运气节点永不截断：创建后其全部数字结局立即展开为子招法节点；爆炸结局不入树，价值显式 0。
- **结局**：点击格子后翻开数字 0~8，或爆炸。数字结局数量 ≤ 9；爆炸 = 1 − 生存概率，是期望公式的闭合缺项。
- **死格**：可能值唯一的格子（点开无信息）。无需特殊处理（§7）。
- **安全格**：死亡概率为 0 的格子；与死亡概率 0.01%、0.02% 的格子完全连续，无任何结构性特殊地位。
- **死亡概率**：候选或局面的失败概率 = 1 − 其当前价值估计。
- **生存概率**：P(点击的格子不是雷) = 1 − P(格子是雷)。概率引擎的精确量。
- **精确值**：某局面的真实最优玩胜率（深度无穷的实测值）。来源：endgame 精确求解（§10.1）。
- **冻结**：把可行方案数足够小的局面交给 EndgameBruteforce 精确求解，得到精确值并使其成为终叶（§10）。
- **终叶**：已冻结的招法节点，值为精确值，之后不再展开、不参与任何轮的资源分配。
- **可证截断**：依据精确量与精确值的比较，证明某候选不可能胜出（§10.2），随后删除其整枝。
- **资源单位**：一次真实引擎调用的成本，记为 1。两类常规调用：局面分析（概率引擎）、结局观察（observe）；endgame 精确求解另计（§10.4）。
- **c 表**：每层一个的指数衰减系数表；第 k 层使用 c[min(k, L−1)]，超出表长的层沿用最后一个值。
- **硬截断①**：候选筛选（§7）。**硬截断②**：冻结与可证截断（§10）。两者是树内容减少的唯一途径。

### 3. 主流程全景

```
启动检查（有确定性落子？→ 交既有确定性逻辑）
 └─ 根分析（1 单位）→ 候选筛选（硬截断①）
     └─ 逐轮加深（全局深度 d → d+1）：
         1. 分配重算（最新深度估计，跳过终叶；O(展开节点数)）
         2. 每叶展开（分析 1 单位 → 规则 A 分候选 → 达标候选按规则 B 全展开结局
            → 规则 C 分配剩余 → 子节点成为下一轮叶子）
         3. 轮末：冻结与可证截断（硬截断②）→ 删除被截断子树 → 预算检查
         4. 预算耗尽 → 终止返回；否则回到 1
```

每步的成本与输出见对应章节。

## 第二部分 模型

### 4. 树：规范形式与硬规则

```
招法节点 s
 ├── 候选 T1 ──→ 运气节点(T1) ──→ 结局 v ──→ 招法节点 s_{T1,v}
 │                              └─ 结局 v' ─→ 招法节点 s_{T1,v'}
 ├── 候选 T2 ──→ …
 └── …（被截断的候选不在树中，如同从未存在）
```

1. 两类节点严格交替：招法节点 → 候选 → 运气节点 → 结局 → 新的招法节点。
2. 不允许悬挂运气节点：运气节点一旦创建，其全部数字结局立即展开为子招法节点。加深之前树上的所有叶子必然是招法节点或终叶；此性质由构造保证，加深前以防御性断言检查。
3. 死格不进入候选池（§7）。若某局面的候选池为空（只剩死格，几乎不可能发生），不特殊处理——任意指定一个死格作为最优解即可。（注释：可能值唯一推不出安全；若想严格，指定最小死亡概率者即可，一行成本，不作要求。）

### 5. 价值递归（闭合）

```
终叶：                    Ŵ(s) = 精确值（§10）
叶子（深度 0 的招法节点）： Ŵ₀(s) = H0(s)
深度 k 的招法节点：         Ŵ_k(s) = max over 已展开候选 of V̂_k(T)
                           若无任何已展开候选，Ŵ_k(s) = H0(s)
深度 k 的候选：             V̂_k(T) = Σ_v P(v|T)·Ŵ_{k−1}(s_{T,v}) + (1 − 生存概率(T))·0
```

- Σ_v P(v|T) = 生存概率(T)；缺失的 1 − 生存概率 即爆炸结局，价值显式 0。公式无缺项、无附加系数。
- 未展开的候选不参与 max（价值尚未被测量，见 §6"等待被搜索"语义）。每个招法节点的分析费已付，H0 恒存在——**递归处处有定义**。
- 精确值超越深度语义：它是深度无穷的实测值，与任何深度 k 的值比较都有效；同一局面一旦有精确值，其低深度估计一律不再使用（精确值优先且唯一）。

### 6. 深度语义与叶子不变量

- **深度定义**：一个决策层 = 招法节点 → 候选 → 运气 → 新局面。加深 = 全局 d → d+1。只有同深度的值之间才做比较；不同深度之间的估计不复用（节点骨架可复用）；精确值除外（§5）。
- **H0**：H0(s) = (4 × s_best + s_second) / 5。s_best、s_second 为候选中最小、次小死亡概率对应的安全概率；候选仅一个时次佳取 0（JS 原语义：blendedSafety = 4/5·bestSafety1）。H0 不是免费的：取 H0 需先付 1 单位分析费。
- **"等待被搜索"语义**：树中每个招法节点的值恒有定义（最低为 H0）。H0 可以出现在期望公式的中间项，代表尚未展开到全局深度的分支——其结果暂时不可信；终止时按 §11 如实报告深度与展开程度，绝不把待搜索部分冒充完整值。
- **运气节点永不截断**：自然随机不可估计；每个结局子局面至少获得 1 单位分析（§9 保底），期望公式不允许任何结局缺项——此项由构造保证。
- **叶子不变量（时刻成立，防御性断言）**：树的所有叶子要么处于当前全局深度（本轮已搜索，值可信），要么是终叶（精确值），要么"等待被搜索"（份额已分配，结果暂时不可信）——不存在部分展开的中间状态参与价值比较。

## 第三部分 机制

### 7. 硬截断①：候选筛选

每个招法节点的候选池由一次局面分析（1 单位）产出的概率网格，按 JS Sweeper 的候选点方法筛选：

- **0.9 概率窗口**：候选 = 安全概率 ≥ 0.9 × 最优安全概率 的格（继承 JS 的 HARD_CUT_OFF 语义）。
- **死格排除**：可能值唯一的格不进入候选池（继承 JS 行为）。

窗口之外的候选从未进入树；除 §10 外无任何移除路径（资源不足不淘汰，§9）。无激活、无复活：被截断的候选永不回归；若优者在窗口之外，本搜索不会找到它——继承 JS 语义的固有代价（§16）。

（可选旋钮，默认不引入：内层窗口宽度是否随深度收紧——参数，语料 A/B 后决定；见 §16。）

### 8. 资源分配

三个规则互不覆盖；每个分配动作必须标明所在层与所用规则。

**规则 A —— 决策层（候选之间）：按优秀程度指数分配**

- d_i：候选的死亡概率输入（当前可得的最深实测估计）——未展开过 = P(格子是雷)（精确量）；已展开过 = 1 − Ŵ(该候选)（随加深更新）。
- d_best = 候选中最小的 d_i；c = c[min(当前层, L−1)]（初值全 2.0）。
- **w_i = exp(−(d_i / d_best) × c)**；r_i = (本节点剩余资源) × w_i / Σ_j w_j。
- 份额低于 1 的候选不淘汰、不截断——按 §9 保底处理。
- **d_best = 0**（存在确定安全候选）：全部资源给安全格（多个安全格均分），其余候选得 0。安全格被充分展开；"先点安全格"由价值 max 链与免费信息事实导出（§5/§6），**不是**本公式的推导结果——公式只决定资源去向。

端点行为（c = 2.0）：死亡 1% 与 1.1%（比值 1.1）→ 份额约 **55/45**；死亡 5% 与 40%（比值 8）→ 份额约 **100/0**（exp(−14) ≈ 1.1×10⁻⁷）；96/4 对应 c ≈ 0.45（该例子若要入文档必须带自己的 c）。比值越接近 1，份额越接近均分（1% vs 1.01% → 约 50.5/49.5）。

**规则 B —— 运气层第一波：强制均匀**

候选被展开（付 1 单位观察费）后，其全部结局子局面在全部被探索完毕之前，任何单个结局不得获得超过 1 单位：每个结局子局面先各付 1 单位分析费，获取各自的 H0 或已有值。即使某结局概率为 99%，也必须等其余结局全部被探索过，剩余资源才进入规则 C。理由：运气层的每个结局局面除概率外地位完全相等——期望公式不允许任何结局缺项。

**规则 C —— 运气层第二波：按死亡概率归一化**

- D_v = 1 − Ŵ(结局子局面 s_v)；r(s_v) = (该候选的剩余资源) × D_v / Σ_v' D_v'。
- 死亡概率高的结局子局面获得更多资源：死亡意味着复杂度（只有被迫猜测才会带来死亡，猜测意味着该区域仍有未解析的决策结构）；"简单但高概率"的结局已在第一波看清（其 H0 误差预计较小——待测），不应继续占用资源。
- 每轮加深时用最新深度估计重新归一化、重新分配——规则 C 与加深轮动态耦合。
- 分母 ΣD_v' = 0（全部子局面确定安全）时死亡归一化无意义，回退为均匀分配——规则 C 唯一的安全回退点。

**分工**：规则 A 决定"选谁深挖"（择优，候选地位不对等——最终只会打出一个）；规则 B 决定"谁至少被看一眼"（期望完整性）；规则 C 决定"看清之后重点看谁"（复杂度导向）。决策层与运气层的不对称是设计意图：决策层按优秀程度倾斜，运气层第一波强制均匀。

### 9. 加深轮与保底

加深动作（全局 d → d+1）：

1. 全树资源分配重算（跳过终叶；用最新深度估计重跑规则 A/C）。节点重算成本 O(其候选数量)，全树合计 O(总展开节点数)，可忽略。
2. 每片叶子获得向上取整后的资源份额（至少 1 单位，见保底）。
3. 每片叶子用其份额展开一层：分析自己（1 单位）→ 规则 A 分候选 → 达标候选（份额 ≥ 1 + 结局数）按规则 B 全展开结局 → 规则 C 分配剩余 → 其子招法节点作为下一轮叶子获得各自的规则 C 份额。
4. 轮末：硬截断②（§10）→ 删除（§10.3）→ 预算检查（§11）。

**保底**：每片叶子每轮至少获得 1 单位（向上取整）。资源不足 1 单位不构成淘汰理由——直接送 1 单位进行观测，允许本轮实际消耗超出名义预算，由轮末预算检查兜底。

**值重算**：加深后叶子值变化，祖先值自底向上重新聚合（纯算术：加权和与取最大，不调用引擎）；终叶不参与。

### 10. 硬截断②：冻结与可证截断（更深的硬截断）

目标：在候选筛选之外，把"已能被精确回答"的区域从搜索中移除——它们继续留在树里只会消耗预算、贡献粗估计。机制由两部分组成：**冻结**（产生精确值，自下而上传播）与**可证截断**（用精确量证明某候选不可能胜出并删除）。全部判定只使用精确量（§10.5）。

**10.1 冻结**

- 触发：任何招法节点完成位置分析后，若其可行摆雷方案数（概率引擎的候选方案数）≤ 冻结上限 C_f，调用 EndgameBruteforce 精确求解该位置（同时产出精确胜率与最优首招）。
- 结果：该节点成为**终叶**——值 = 精确值；之后不再展开、不参与资源分配；其任何低深度估计作废（§5 精确值优先）。
- 冻结尝试是单次的：方案数是分析产出的固定量，不随加深改变；C_f 越大可冻结区域越大、单次调用越贵（§10.4）。根层若方案数 ≤ C_f，直接返回精确解，搜索无需展开。

**10.2 可证截断（冻结的传播与侧向收紧）**

设某候选 T* 的全部结局子局面均为终叶（已冻结），则 T* 的价值 V̂(T*) = Σ_v P(v|T*)·Ŵ(s_{T*,v}) 是**精确值**（记为 V̂*）。此时对任一其他候选 T′：

> 若 生存概率(T′) ≤ V̂*（生存概率是引擎精确量；任意候选的真值恒 ≤ 其生存概率——精确不等式），则 T′ 即使拥有完美的后续信息也不可能超过 T*——**T′ 可证不参与 max**。

- 截断 T′ 后 max 不变（不等式保证），因此删除是值安全的。
- 若除 T* 外全部候选均可证截断 → 该节点值 = V̂* → 节点冻结为终叶 → 向上传播（父候选因此可能变精确，继续侧向收紧）。
- 排除规则：当前最优候选 T* 本身永不被此条截断（其生存概率 ≥ 自身价值 V̂*，条件恒不满足）——候选池不可能被清空。
- 效果方向：冻结自下而上传播精确值，可证截断自上而下删除失格候选。"更深的硬截断"即指这一过程在整棵树上反复发生，而不是只在候选池创建时发生一次。

**10.3 删除（从树中摘除被截断的节点）**

两种删除对象：

- **候选级**：可证截断的候选及其运气节点、全部后代整枝删除。父节点 max 参照集收缩（值不变，§10.2 不等式保证）。
- **节点级**：被冻结为终叶的节点的**后代**整枝删除（节点本身保留为终叶——它是父期望公式的必需项，只有其子树不再需要）。

执行规则：

- **时机**：判定发生在轮内（展开与冻结传播时只做标记），删除统一延迟到**轮末**（加深步骤 1 的重分配之前，与预算检查同点）——轮内遍历不产生悬垂引用。
- **内存**：搜索树使用专用 Arena 池（稠密句柄 = 池内下标，沿用 core/types.h 的句柄惯例）；删除 = 子树后序回收 → 空闲链表 → 后续分配复用；被截断候选的子句柄从父节点清除。
- **防御性断言**：待删除子树内不含任何仍被祖先引用的值（已记录的冻结值除外）；删除后立即自底向上重聚合祖先值；删除后所有叶子满足 §6 叶子不变量，方可开始下一轮。

**10.4 成本与参数**

- 冻结调用 = 一次 endgame 求解，成本按真实引擎调用计入资源账本并如实上报（它比 1 单位分析贵得多）；冻结尝试只对方案数 ≤ C_f 的位置发起，不做盲试。
- 新增参数：**冻结上限 C_f**（初值建议 5000；上限为代码库的 kMaxBruteforceCount = 200000；校准标准：触发率 × 单次成本 对 胜率/内存 的实测权衡，§15）。
- 与规则 B/C 的交互：终叶不消耗资源，其释放的份额在下轮按规则 A/C 自然重分配。

**10.5 禁用边界（防软淘汰退化）**

截断判定只允许使用：引擎精确量（P(雷)、生存概率、可行方案数）与冻结后的精确值。**任何基于测量值（深度 k 估计、H0）大小比较的截断/淘汰均被禁止**——测量值可能随加深下修，用它裁枝会重蹈"资源不足淘汰"的覆辙。此边界是硬约束：删除前必须存在精确值依据或方案数依据。

### 11. 终止与返回

0. 启动检查：存在确定性落子 → 交既有确定性逻辑；搜索只在无确定性落子的局面启动。
1. 根分析（1 单位）→ 候选筛选（硬截断①）。若池中只剩一个候选，直接返回它（自然情形，不是终止机制）。
2. 加深轮（§9 四步）。
3. 轮末预算检查：预算耗尽 → 终止。

**终止条件只有一条：预算耗尽。** 返回根层当前价值最优者，并如实报告：评估深度 d、每个候选的子树展开程度、冻结与截断统计（冻结次数、可证截断枝数、删除节点数、实际消耗 vs 名义预算）。估值与真值的差额在无 UB/LB 约束下无界、无保证，其分布由语料测出并上报。不设定案阈值 Δ。

## 第四部分 工程与验证

### 12. 规模与复杂度

- 完全展开模式下，每加深一层节点数以 c̄×k̄ 增长（c̄ = 每局面平均候选数，k̄ = 每候选平均结局数；典型 expert 场面约 10×3）。具体数值以 anytime 实测为准。
- 资源聚焦（规则 A/C）+ 终叶不消耗 + 截断删除：预算集中于少数优秀候选的主链；总引擎调用 ≤ 总预算 + 保底超支部分（超支量级 ≈ 末轮叶子数 × 平均展开成本 + 冻结调用，终止时如实上报）。
- 全树资源重算 O(总展开节点数)，相对引擎调用可忽略。
- 内存：树只增不减，冻结删除提供唯一的中程释放源；上限与累计展开节点数线性相关——冻结触发率越高，内存曲线越平（待实测，§15）。

### 14. 与 JS Sweeper 的关系

**继承清单**（原样继承，来源可查）：候选点方法（0.9 窗口 + 死格排除 = 硬截断①）；H0 混合 4:1（含无次佳时 4/5·best 的原语义）；"trivial 分析先行"的分层思想；1-ply 期望安全前瞻（secondarySafetyAnalysis）的概念内核。

**差异清单**（本设计自有的）：比值式指数分配（JS 无资源分配机制）；运气层强制均匀第一波与死亡归一化第二波（JS 无）；全局同深度逐轮展开（JS 受毫秒级成本限制只能 1-ply）；冻结与可证截断（JS 无精确求解通道）；除继承窗口外无任何阈值、无 UB/LB 估计；全程同深度比较。

**实证参考**：JS 在 5 盘实测中 1 胜 4 负、155 步（ref/ 日志可复现）；其 0.9 窗口在解数 5.87×10⁶¹ 的局面筛出 5 个候选（实录可复现）。本设计正确性以语料实验判定，不凭推理断言。

### 15. 验证计划（防糊弄原则的落实）

- **前置设施**：整盘对弈 playout 基准（固定种子集，覆盖 expert 与大棋盘；代码库目前无此设施，第一项必做工作）。
- **等价性测试**：深度 1 搜索与 JS Sweeper 对照推荐落子，分两组跑——冻结开 / 冻结关（冻结会让部分叶子携带精确值，须先隔离归因）；分歧按机制分项归因（JS 另有 progress/fiftyFifty 等项）。
- **真值标签实验**（低成本先行）：cap 内盘面用 EndgameBruteforce 逐候选精确胜数作真值，测深度 1/2 估计的偏置与方差——不依赖 playout 设施；顺带统计死格携带正死亡概率的出现率。
- **冻结专项**：C_f 各取值下的触发率、单次 endgame 平均成本、冻结开/关对胜率与内存的影响（逐项前后对比）。
- **截断专项**：每盘报告可证截断的枝数与删除的节点数（证明机制确实运作）、截断前后树大小对比。
- **逐项基准**：同一语料上分别测量"纯概率选点"（基线）、"深度 1"、"深度 2"、"c 表不同取值"、"窗口 0.9/0.95/无窗口"的胜率、步数、被迫猜测次数、引擎调用数、最坏预算消耗。
- **最坏情况**：大棋盘（100×100/2500 级）预算与内存表现。
- **失败记录**：所有失败如实记录（含本设计自己的缺陷），不以"调整参数后重测"掩盖。

### 16. 已知权衡与开放项（不掩盖）

- **0 结局无级联展开**：模型对 0 结局的价值估计低于真实级联收益——影响幅度需语料测量。
- **硬截断①不可逆**：窗口外的候选从未存在；若真正优者在窗口外，翻案不可能——继承 JS 语义，接受。
- **冻结区域受限**：只有可行方案数 ≤ C_f 的位置受益；巨大方案数的中盘主脊不冻结，H0 与加深照旧。
- **冻结成本未知**：单次 endgame 求解可能很贵（方案数接近 C_f 时）——C_f 标定依赖 §15 实测。
- **删除后的转置重建**：无转置表，被删子树可能经另一路径被重新展开——浪费但不影响正确性；是否引入转置表由实测成本决定。
- **H0 中间项**：期望公式中"等待被搜索"分支的值暂时不可信——上报包含深度与展开程度，决策质量影响待测。
- **深度受预算限制**：完全展开必然撞墙，c 表是深度/宽度权衡的唯一旋钮（语料校准）。
- **内层窗口收紧**（§7 可选旋钮）：暂不引入，语料需要时再议。
- **50/50 结构检测**：暂缓，搜索验证后再评估。
- **转置局面未去重**：当前按树展开，可能重复分析同一局面；需要与否由实测决定。
